This document outlines the process for creating a comprehensive matching file that links Biosynthetic Gene Clusters (BGCs) from the MIBiG database with tandem mass spectra (MS/MS) from the Global Natural Products Social Molecular Networking (GNPS) database. The entire workflow is implemented in the json_to_tabular.ipynb Jupyter notebook.

  The core idea is to match entries from both databases based on their shared chemical structures,
  standardized using InChIKeys.

  **Workflow Overview**

  The process can be broken down into four main stages:

   1. Data Acquisition: Downloading the necessary datasets from MIBiG and GNPS.
   2. Data Parsing and Processing: Extracting relevant information from the raw JSON files into
      structured tabular formats (CSVs).
   3. Structure Standardization: Converting chemical structures (represented as SMILES) into standardized InChIKey connectivity layers for robust matching.
   4. Merging: Joining the processed MIBiG and GNPS tables based on the shared structural identifier to create the final matching file.

  ---

  **Step-by-Step Guide**

  1. Data Acquisition

  First, you need to download the raw data from both MIBiG and GNPS.

   * MIBiG Data (v4.0):
   1     wget https://dl.secondarymetabolites.org/mibig/mibig_json_4.0.tar.gz
   2     tar -xzvf mibig_json_4.0.tar.gz

   * GNPS Data:
   1     wget https://external.gnps2.org/gnpslibrary/ALL_GNPS.json

  Place the downloaded and extracted files in a designated datasets directory for the notebook to
  access.

  2. Data Parsing and Processing

  The json_to_tabular.ipynb notebook handles the parsing of the raw JSON files.

   * Parsing MIBiG JSON Files:
       * The parse_mibig_json function iterates through each BGC's JSON file.
       * For each BGC, which may contain multiple compounds, it uses a heuristic to select a single
         "main" compound. The priority is:
           1. A compound with listed bioactivities.
           2. If none, a compound with a database ID (e.g., PubChem).
           3. If none, the first compound in the list.
       * It extracts the accession number, compound name, and SMILES structure for the main compound.
       * The result is saved as mibig_compounds.csv.

   * Parsing GNPS JSON File:
       * The process_gnps_json function processes the large ALL_GNPS.json file.
       * Since a single spectrum ID can have multiple entries, the function groups them and selects the "best" entry based on a quality score (preferring entries with SMILES and InChIKey information).
       * It extracts the spectrum ID, compound name, and SMILES string.
       * The result is saved as gnps_spectra_processed.csv.

  3. Structure Standardization with RDKit

  This is the most critical step for ensuring accurate matching.

   * SMILES to InChIKey: The notebook uses the rdkit library to convert the SMILES strings from both the MIBiG and GNPS dataframes into standardized InChIKeys.
   * Connectivity Layer Extraction: To avoid mismatches due to stereochemistry, the process uses the InChIKey connectivity layer. This is the first 14-character block of the full InChIKey, which represents the molecule's graph structure.
   * Two new columns, InChIKey_smiles (the full key) and inchikey_connectivity (the first 14
     characters), are added to both dataframes.

  4. Merging to Create the Final File

   * After both the MIBiG and GNPS dataframes have been processed and contain an inchikey_connectivity column, they are merged.
   * The merge operation joins rows from both tables where the inchikey_connectivity value is identical.
   * The final output is a single table that maps MIBiG BGC accessions to GNPS spectrum IDs, forming the BGC_GNPS_matching_file.

### File Description: `main_compound01.csv`

This file is a processed and standardized tabular representation of the MIBiG (Minimum Information about a Biosynthetic Gene Cluster) database. It is an enhanced version of the initial `mibig_compounds.csv`, with added columns containing standardized chemical identifiers generated by RDKit.

The primary purpose of this file is to create a clean, machine-readable dataset where each Biosynthetic Gene Cluster (BGC) is linked to standardized structural identifiers (InChIKeys). This allows for robust matching against other chemical datasets, such as the GNPS spectral libraries.

#### Column Descriptions

Here is a breakdown of each column in the `main_compound01.csv` file:

| Column Name | Description |
| :--- | :--- |
| `accession` | The unique MIBiG accession ID for the Biosynthetic Gene Cluster (e.g., `BGC0000001`). |
| `compound_names` | A Python-style list of all compound names associated with the BGC entry. |
| `structures` | A list of SMILES strings, with each SMILES corresponding to a compound in the `compound_names` list. |
| `masses` | A list of molecular masses for each compound in the entry. |
| `formulas` | A list of molecular formulas for each compound in the entry. |
| `inchikeys` | A list of the full, 27-character InChIKeys generated from the corresponding SMILES in the `structures` list. |
| `connectivity_layers`| A list of the 14-character InChIKey connectivity layers derived from the `inchikeys` list. |
| `inchikey` | The full, 27-character unique InChIKey. |
| `connectivity_layer` | The **primary key for matching**. This is the 14-character unique connectivity layer extracted from `inchikeys`. It represents the molecule's structural graph, making it robust to differences in stereochemistry.

- Based on the shared `inchikey` between mibig and gnps files, `BGC_accessions` column has been added to the `gnps_mibig_match01.csv`, representing the linked BGCs to every GNPS spectrum.
